# Проверка требований и результаты

Проверка от 24.10.2026 по приложенным `lab1.md`, `common_requirements.md`,
`checklist.md`. Исходная версия: `EG11CH/ppois_labs`, ветка
`feature/lab1-dictionary-set`, коммит `79baf706d0df4cf0e49a6013e66240414d7a0822`.
Проверены оба реализованных варианта — 1.2 и 1.4.1.
Архив содержит локальные изменения относительно этого коммита.

## Что было до упрощения

Исходная версия прошла 52 проверки CTest; покрытие строк — 626/629 = 99,5%.
Функциональных нарушений выбранных вариантов в выполненных тестах не выявлено.
При этом итеративные обходы дерева, указатель на владеющий указатель,
`std::function`, лямбды и ряд алгоритмов STL усложняли объяснение.
Старый отчёт проверки содержал уже устаревшее сообщение об отсутствии ссылки
на репозиторий. Отчёт заменён результатами новой проверки.

При чтении публичного GitHub API обнаружено:

- Для исходного коммита есть успешный запуск CI:
  https://github.com/EG11CH/ppois_labs/actions/runs/38035752884
- Релиз https://github.com/EG11CH/ppois_labs/releases/tag/lab1-v1.0.0 опубликован,
  но список его прикреплённых файлов (`assets`) на момент проверки пуст.
  Автоматические ссылки GitHub на исходники не являются готовыми программами.
  Поэтому требование о скачиваемом исполняемом артефакте ещё не подтверждено.

## Что упрощено

- Вставка, удаление, копирование и обход дерева выражены обычной рекурсией.
  Отдельные указатели на владеющие указатели, список пар для обхода и
  вращения дерева при очистке удалены.
- В сравнении и выводе множества, проверке кавычек используются обычные циклы
  вместо лямбд и `all_of`/`transform`/`any_of`.
- Общий механизм меню с `std::function` заменён прямым циклом каждого меню.
- В CMake одна библиотека `lab1` вместо трёх вспомогательных целей.
  Две программы и разделение CLI/классов сохранены.
- Две функции `main` перенесены из отдельной папки `app` в `cli`.
- Вместо повторяющихся README и старых пояснений оставлены один корневой README,
  разбор для защиты и этот отчёт. Служебные скрипты оставлены по требованиям.
- Публикация релиза умеет загрузить архив в уже существующий релиз.
  Отсутствие файла при загрузке артефакта в CI теперь считается ошибкой.

Сложные конструкции не заменялись ручным управлением памятью.
`unique_ptr` и глубокое копирование сохранены, чтобы не создавать утечки
и совместное владение одним деревом у двух словарей.

неопределённого поведения в выполненных сценариях.

Покрытие — именно покрытие строк, не всех ветвей и возможных состояний.

После изменений C++ используйте новую папку сборки или очистите счётчики.

## Ограничения и оставшиеся действия

1. Рекурсивное дерево проще, но глубина вызовов зависит от высоты дерева.
   Проверена цепочка из 1500 узлов; устойчивость к произвольно глубокой
   цепочке не заявляется. Дерево не балансируется.
2. Загрузка словаря допускает до 1 000 000 записей; это ограничение формата
   не является гарантией достаточного стека для любого порядка этих записей.
3. Булеан по умолчанию ограничен 4096 подмножествами, разбор множеств —
   64 уровнями. Лимиты именованы; лимит булеана передаётся параметром.
4. Требование о готовом артефакте нужно завершить публикацией нового тега
   после отправки исправлений в `feature/lab1-dictionary-set`. Пример —
   `lab1-v1.0.1`. Старый тег автоматически не обновляется при новом коммите.
5. Одобрение преподавателя, прохождение защиты и проверку на плагиат нельзя
   подтвердить локальными тестами. В main работа должна попасть через
   одобренный преподавателем PR.

Требования о 50 классах, 150 полях и 100 поведениях относятся к лабораторным
№2 и №3. Для №1 они не нужны. Итоговая мини-лекция относится ко всему курсу.
В задании №1 достаточно одного варианта; здесь сохранены оба уже реализованных.
