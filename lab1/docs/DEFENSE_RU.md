# Как разобраться в коде перед защитой

## Порядок чтения

1. `EnglishRussianDictionary.h`: публичные операции словаря.
2. `EnglishRussianDictionary.cpp`: `Node`, `findNode`, `insertNode`, `removeRoot`.
3. `SetElement.h` и `.cpp`: два вида элемента.
4. `Set.cpp`: `add`, `operator[]`, операции множеств, `appendSubsets`.
5. `parseSet`, `parseElement`, `parseAtom`: разбор строки.
6. `cli`: цикл меню и вызов нужной операции.
7. `tests`: примеры правильного результата и обработки ошибок.

## Обозначения C++, которые здесь нужны

| Запись | Смысл |
|---|---|
| `.h` / `.cpp` | Объявление класса / реализация методов |
| `private` / `public` | Внутреннее устройство / доступные пользователю операции |
| `const Set& other` | Другое множество передано без копирования и не изменяется через эту ссылку |
| `const` после метода | Метод не меняет поля объекта напрямую |
| `std::vector<T>` | Растущий массив объектов типа `T` |
| `std::pair<A, B>` | Два значения: `.first` и `.second` |
| `using Entry = ...` | Короткое имя типа; отдельный новый класс не создаётся |
| `auto` | Компилятор выводит тип из правой части |
| `nullptr` | Указатель не указывает на объект |
| `pointer->field` | Доступ к полю объекта через указатель |
| `*pointer` | Объект, на который указывает указатель |
| `std::unique_ptr<T>` | Владеющий указатель: уничтожает объект автоматически |
| `std::make_unique<T>(...)` | Создаёт объект и возвращает владеющий указатель |
| `.get()` / `.reset()` | Получить обычный указатель / освободить принадлежащий объект |
| `std::move(value)` | Разрешает передать ресурсы; само выражение ничего не переносит |
| `= default` | Попросить компилятор создать стандартную реализацию |
| `noexcept` | Функция обещает не выпускать исключения наружу |
| `throw` / `try` / `catch` | Сообщить об ошибке / выполнить код / обработать ошибку |
| `friend` | Разрешить внешней функции доступ к закрытым полям класса |

`unique_ptr` оставлен намеренно: вручную писать `new` и `delete` здесь
не нужно. Каждый узел дерева принадлежит ровно одному указателю.
Временный обычный `Node*` используется для поиска и памятью не владеет.

## Словарь: почему дерево

В каждом `Node` находятся `entry` и два указателя: `left`, `right`.
Первое поле пары — ключ, второе — перевод. `root_` владеет корнем.
`wordCount_` хранит количество записей, поэтому `size()` работает за O(1).

Инвариант дерева: все слова слева меньше ключа текущего узла,
все слова справа больше. Сравниваются строки C++; регистр имеет значение.

### Поиск и вставка

Если добавить `dog`, затем `cat` и `tree`, корнем будет `dog`,
слева `cat`, справа `tree`. Поиск `tree`: сравнить с `dog`, перейти вправо,
сравнить с `tree`, вернуть найденный узел. Пустой указатель означает,
что слова нет.

`insertNode` действует по тому же правилу. Если нужная ветвь пуста,
создаётся новый узел. Иначе функция вызывает себя для левой или правой
ветви. Это **рекурсия**: задача для дерева сводится к той же задаче
для меньшего поддерева.

Параметр `std::unique_ptr<Node>& node` — ссылка на владеющий указатель.
Благодаря ссылке присваивание `node = ...` меняет именно нужную ветвь,
а не локальную копию указателя. Указателя на указатель в новой версии нет.

`operator+=` проверяет ключ, вызывает вставку, увеличивает счётчик.
При повторном ключе вставка бросает исключение, счётчик не увеличивается.
`[]` возвращает **ссылку на перевод**, поэтому его можно и прочитать,
и изменить: `dictionary["cat"] = "кошка"`.

### Удаление

`removeNode` сначала ищет ключ, затем вызывает `removeRoot` для найденного
поддерева. Слово «root» здесь означает корень выбранной ветви, не обязательно
корень всего словаря.

Три случая:

1. Нет потомков: указатель на узел заменяется пустым.
2. Один потомок: этот потомок занимает место удалённого узла.
3. Два потомка: берём минимальный узел справа, меняем пары слов местами,
   затем удаляем прежний ключ из правого поддерева.

Пример третьего случая: корень `m`, слева `a`, справа `z`, у `z` слева `t`.
При удалении `m` следующим ключом будет `t`. После обмена `t` оказывается
в корне, старый `m` — на прежнем месте `t`, откуда он удаляется.
Если у этого узла был правый потомок, он сохраняется.

Локальный `removed` временно владеет старым узлом. Его потомок передаётся
новому владельцу через `std::move`; старый узел освобождается автоматически.
Количество записей уменьшается один раз, если удаление состоялось.

### Копирование, сравнение и ввод

Обычное копирование адреса дерева связало бы два словаря с одной памятью.
`cloneTree` создаёт новый узел, рекурсивно копирует левую и правую ветвь.
В итоге изменение копии не затрагивает исходный объект.

Копирующее присваивание сначала создаёт независимую копию, затем обменивает
данные через `swap`. Если создание копии не удалось, исходные данные
присваиваемого объекта ещё не изменены. `this != &other` защищает от
присваивания объекта самому себе. `return *this` возвращает текущий объект.

Деревья одинаковых словарей могут иметь разную форму. `collectEntries`
обходит дерево в порядке «левое — текущий узел — правое», получая
отсортированные пары. `==` сравнивает эти пары, а не адреса и не форму дерева.

`<<` записывает число пар и пары в кавычках. `std::quoted` умеет сохранять
пробелы, кавычки и обратную косую черту внутри строк. `>>` сначала читает
в отдельный словарь. Только при успехе он заменяет текущие данные.
`loadFromFile` дополнительно проверяет открытие файла и отсутствие лишнего текста.

Дерево не балансируется. Операции поиска, вставки и удаления требуют O(h),
где h — высота дерева: около O(log n) при хорошем распределении и O(n)
для цепочки. Рекурсивные операции используют O(h) памяти стека.
Очень глубокая цепочка может исчерпать стек; проверен случай 1500 узлов.
Это компромисс упрощённой учебной реализации.

## Множество и его элемент

`SetElement` содержит строку `atom_` и указатель `nestedSet_`.
Если указатель непустой, элемент является вложенным множеством;
иначе это строковый атом. Копия вложенного множества создаётся отдельно.

`Set` хранит элементы в закрытом `vector`. Порядок хранения не означает
математический порядок: `{a, b}` и `{b, a}` равны.
`{}` пусто, а `{{}}` содержит один элемент. Строка `"{a}"` и множество `{a}`
имеют разные типы и не равны.

`set[element]` ищет элемент через `std::find`: эта стандартная функция
последовательно сравнивает элементы. Результат `end()` означает «не найден».
`add` использует эту проверку, чтобы не добавлять повторы. `remove` удаляет
найденный элемент через `vector::erase`.

Операции:

- `A + B`: скопировать A и добавить элементы B без повторов.
- `A * B`: оставить элементы A, которые присутствуют и в B.
- `A - B`: оставить элементы A, которых нет в B.
- Составные операторы `+=`, `*=`, `-=` записывают результат в A.
- `==`: мощности равны и каждый элемент слева есть справа.

Для атомов поиск линейный, O(n); операции двух множеств могут потребовать
O(n × m) сравнений. Для вложенных элементов сами сравнения тоже требуют работы.

### Булеан

Булеан — множество всех подмножеств. Для `{a, b}`:
`{{}, {a}, {b}, {a, b}}`.

Алгоритм начинается со списка из одного пустого подмножества.
Для `a` добавляется копия пустого множества с `a`.
Для `b` копируются **только прежние** два подмножества, в каждую копию
добавляется `b`. Поэтому запоминается `previousSize`, а не используется
меняющийся размер списка.

Каждый новый элемент удваивает число подмножеств: их 2^n.
`checkedSubsetCount` заранее проверяет лимит и переполнение.
4096 — именованный лимит по умолчанию; его можно передать явно.
Материализация всех подмножеств требует экспоненциальных ресурсов.

### Разбор строки

`parseSet` ожидает `{`, затем читает элементы до `}`.
`parseElement` проверяет следующий символ: `{` начинает вложенное множество,
иначе читается атом функцией `parseAtom`. Вложенность разбирается рекурсивно.

`consumeSeparator` принимает только запятую или закрывающую скобку.
`requireEnd` проверяет отсутствие лишнего текста после объекта.
Поэтому `{a,}` и `{} extra` считаются ошибками.
Глубина ограничена именованной константой `maxParseDepth`.

## Меню, тесты и служебные файлы

`dictionary_main.cpp` и `set_main.cpp` передают `std::cin` и `std::cout`
соответствующему меню. Меню читает команду, `switch` выбирает операцию,
исключение превращается в сообщение «Ошибка», после чего можно продолжить.
Классы словаря и множества ничего не знают о меню.

Потоки передаются параметрами, поэтому тесты могут вместо клавиатуры подать
`istringstream`, а вместо экрана использовать `ostringstream`.
В Catch2 `TEST_CASE` объявляет тест, `REQUIRE` проверяет условие,
`REQUIRE_THROWS_AS` проверяет ожидаемое исключение.

CMake управляет сборкой. Doxygen создаёт HTML по объявлениям классов.
Python-скрипты отдельно измеряют покрытие, проверяют запуск настоящих программ
и упаковывают релиз. GitHub Actions выполняет эти команды на сервере.
Эти инструменты требуются заданием и не являются дополнительными классами домена.

Перед защитой проследите на бумаге вставку и удаление узла с двумя потомками,
построение булеана `{a, b}` и разбор `{a, {b}, {}}`.
Затем объясните, почему изменение копии не меняет оригинал.
